## Required interaction and visual contract

1. **Dismissal:** keep meaningful Playback devices header; no visible Close, replacement in-app Back or blank reserved Close slot. Native sheet drag/swipe, scrim, system Back and accessibility dismiss remain usable, with IME first when editing and no double-pop/trap. Open/dismiss/collapse do not change output or stop playback.
2. **Whole row:** tapping available card padding, identity or status selects that exact device once through existing `onSelect` → `coordinator.select(id)`. No little status/info link islands, duplicate invisible Play button, or leftover footer. Use modest square native rows, coherent focus/ripple, bounded long names and stable trailing Rename geometry. Do not redesign the app or inflate rows to replace removed controls.
3. **Independent rename:** Rename, text field, cursor/text selection, Save and Cancel never select output or bubble to the row. Keep 48dp nonoverlapping actionable regions, including accessibility touch expansion. Full-card selection excludes the independent editor/action regions (disable the parent selection during that row's editing if needed); other eligible rows stay usable. Preserve draft/focus/IME, trim/1–64 validation, accepted-name persistence, one write on Save, no write on Cancel and uncertain-write/no-replay safeguards. Preserve current view-only restrictions; do not expose newly enabled rename/transfer capabilities.
4. **Truthful admission:** retain the current selection predicate: `available && deviceId.isNotEmpty() && !selected && (!active || selectedDeviceId.isNotEmpty())`. Thus confirmed current with no pending alternative cannot redundantly transfer; current active may be chosen to supersede a pending different target. Unavailable/view-only/current-selected/latest-pending choices remain nonactionable as appropriate; **other available targets remain immediately selectable** during transfer/quarantine. No modal-wide disable/veil. Report authoritative active/paused/playing/needs-tap state, not optimistic Playing or confirmed-active styling on request. Pending is distinguishable from confirmed active without relying on color alone.
5. **Accessible selection:** each row has one named device-specific selection action and appropriate enabled/selected/state semantics, not an unnamed clickable Surface or repeated generic label. TalkBack identifies the device, current confirmed output versus pending request, availability and playback truth; Rename is a separate named action, editor/Save/Cancel remain traversable. Requested selection semantics must not imply confirmed authority. No opaque IDs/private paths in labels. Selection is only an explicit action, never a composition/visual-state side effect.
6. **Quiet switching:** no top transient Selecting output / waiting-for-players / success-progress paragraphs, visible Loading text, or switch-only in-flow progress that changes sheet/list geometry. Replace routine switch narration with a **small native ring overlaid on the latest requested target row**, not a new line, row-height change or whole-modal overlay. No label shifts or focus/hit interception, especially Rename; ring must not change scroll, row pitch, sheet anchors or content budget. Accessible contextual pending status may be nonvisual and must not repeatedly reannounce each heartbeat.
7. **Latest intent only:** A→B→A immediately moves the single ring to latest A even while old A/B responses are delayed; old completion/failure must not clear/revive a newer request's ring, including same-target ABA. Reuse existing selection version/intent and transfer identity observations if a token is necessary. After local request completion, a matching accepted transfer may still be in progress; don't clear early merely because `selectionUnconfirmed` became false. Conversely stale server transfer metadata must not move it back from a newer queued choice. Remove ring on matching completion/terminal failure or lifecycle/auth disposal; no ring for ordinary heartbeat/progress/retry network traffic without a real target selection/transfer. Existing bounded transfer/quarantine waiting stays bounded; terminal/uncertain/timeout conditions must expose guidance rather than masquerade as confirmed start or endless busy. Do not introduce new playback deadlines, polling or replay to obtain presentation state.
8. **Retained guidance:** keep concise readable real auth/unavailable/uncertain-write/no-replay/timeout/media/blocked/needs-tap/validation errors and useful recovery, even alongside another pending selection. Preserve separate **Continue playback here** on genuine local needs-tap and truthful **Retry connection** using existing recovery/in-flight matrix. View-only capability and honest first-load/empty/recovery remain; absent data is not empty success. No blanket message suppression, string parsing, hiding all text, or treating every quarantine as successful playback. Routine bounded waiting narration can be quiet; an actual failure/uncertainty explaining paused recovery remains readable.
