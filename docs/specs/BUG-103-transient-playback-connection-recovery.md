## Contract: observation is not permission

Once the server is healthy and a **fresh deliberate valid action** can be admitted, the app must not remain permanently locally stuck or require replacing the queue by selecting an exact track as a hidden reset. Reconnection may verify the connection and expose accurate state/readiness; it never resumes old music or replays old actions. If admission is not yet possible, show a truthful, reachable recovery/refusal rather than false Playing, an empty notice or endless busy state.

Preserve full queue and duplicate keys, current occurrence, elapsed position, realized traversal/baseline, context, repeat/shuffle, origins/pending High, and current history event/progress/reported state. An unchanged-current High/Low/Next edit preserves playing/paused/buffering/idle/error state and does not prepare/start/seek. Empty→first or an actual different-current queue intent attempts start once under the existing rules. A same-event Resume is not a new history traversal; genuinely ended/Previous restart keeps its existing witnessed new-event semantics. Only observed audible progress qualifies history; an uncertain history POST remains one attempt.

Legitimate permission loss (lease expiry, owner/session replacement, uncertain execution/ACK, focus/noisy cancellation, service disposal) stays stopped until a new valid deliberate admission. Cached/restored/server display is never authority. No passive reconnect/startup autoplay, remote-unavailable fallback, automatic claim/queue/ACK-write replay, global uncertainty clearing, refreshed-epoch takeover, stale-key refresh or lease/session/ABA weakening. Preserve original one-shot writes, exact-origin authenticated API/art/audio/range client, TLS/default hostname verification, no authenticated redirects, privacy, focus/FGS and bounded shutdown/resource policies.

### Recovery/identity state, not interchangeable booleans

- `PlaybackCoordinator.fenceLocal` (`:435–451`) increments generation, sets `leaseDeadline=0`, `released=true`, **`activatedEpoch=0`**, `recoverPaused=true`, revokes atomic permit, disables queue intents and calls endpoint suspension for invalidating fences. `Media3PlaybackEndpoint.suspendOutput` invalidates `PlaybackRequests`; service `suspendBufferedOutput` (`:767–785`) clears its authority/request epoch/start tokens and stops/discards buffering but retains prepared items/history/position. Retained queue ≠ activated output.
- Heartbeat remains one serialized attempt per ~1s (`Coordinator.setServiceActive`); `retry()` schedules a fresh verification/poll, not the lost command. `request/consume` (`:1163–1328`) accepts a fresh own-device poll, conservatively sets lease from **request sent time + leaseMs − 2000**, marks connected/recovery NONE, and only after a clean own poll clears `uncertainConnection`. GET/error reconciliation is display-only, never authority. A successful poll does **not** set `activatedEpoch` or install service authority. Remote snapshots never provide local history.
- `consume.canQueueIntent` requires accepted binding plus available output/no transfer/quarantine, and for local nonempty output, **`activatedEpoch == epoch`**. `currentAuthority()` also needs activation; internal `executionAuthority()` can exist after a successful fresh own poll before local activation. These identities are separate from server Binding `{outputDeviceId,receiverId,revision,currentKey,currentEventId}` and are not saved credentials/authority.
- `explicitLocalPlay` (`:699–830`) has a <=12s memory-only originating intent, rejects uncertainty/recovery/conflicting selection/pending commands, and uses one fresh exact-epoch guarded self claim only if genuinely unselected. Claim staging/activation/terminal ACK remain fenced; High uses queue-preserving paused handoff, not replacement blank staging. Matching-activation exceptions and `abandonedClaims` do not authorize generic recovery. The landed `HandoffWitness/reconcileHandoffInbox` exception is only the matching **rejected empty inbox stale-epoch poll**, with no sent state/ACK/write; fresh own poll and exact activation still required. Never generalize it to lost responses/5xx/unknown ACKs.
