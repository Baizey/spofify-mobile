## Acceptance contract

1. **One native continuous interaction across the inventory.** Remove visible Next/Previous pagination, inline See/Show-more fetch buttons, Page N and technical offsets/cursors/ranges. Keep meaningful counts where useful, navigation to full lists and explicit Refresh/stale recovery. Each visible list/group loads its next bounded batch near its loaded frontier with a compact accessible loading state; useful empty/end state and minimum 48dp Retry. No new filters, query policy, UI framework, backend endpoint, page-size increase or whole-state rewrite.
2. **Demand-bounded loading.** Use actual finite lazy viewport/visible indices, not composition of an offscreen footer alone. Reserve single flight synchronously per logical list/group/query, with stable demand/request identity. A layout/progress/recomposition storm cannot repeatedly request the same frontier. Successful append re-arms only on genuine new visible near-end demand; handle a short first batch/large viewport with bounded fill, not a self-draining loop. Stop on end, empty response, stale data, error, repeated/nonadvancing cursor or no identity/position progress. Preserve server bounds (including catalog offset bound); do not silently spin past them or claim complete results when a contract/progress error occurred. No hidden offscreen or background whole-library prefetch; leaving the route/lifecycle cancels demand.
3. **Grouped Search stays useful.** Empty/blank Search issues no match-all request; keep debounce, IME composition, Artists → Albums → Songs ordering, no visible type/count headings and existing nonverbal/accessibility cues. Demand is **per visible section frontier**, not all groups just because the overall list end appears. Never drain offscreen Artists or keep expanding an earlier group while the user is browsing Songs. Appending earlier groups must not jump the current visible anchor, starve later groups or create an automatic cascading preload loop. Preserve bottom query/chrome/IME budget and usable partial groups on error.
4. **Stable append, exact identities.** Keep existing rows/order and list anchor/offset while appending. Deduplicate repeated page identities, **not track IDs**: manual entry IDs and derived occurrence IDs preserve separate duplicates, signed tokens and bindings; catalog entities use kind+ID, playlist targets playlist IDs, likes their existing unique-song identity. Advance backend offsets from validated raw consumed positions/page contract, never from deduplicated visible count or a guessed next display index. Detect nonprogress/overlap inconsistencies without silently skipping/reordering. Current `SearchRoute` keys contain `section.offset` and index; establish correct stable append identity scoped to query/navigation generation rather than blindly rewriting keys. Supply contract + host proof of Back/scroll stability and ABA invalidation.
5. **Maintain existing security/source fences.** Cancel/fence old append results on route/query/filter/release-group/session/client/reset changes, including A→B→A and cancellation-ignoring responses. Appending unchanged source data must not invalidate an existing valid row/More/held-gesture action merely because a read began or another row appeared. Keep genuine revision/fence/output/session changes invalidating it. In particular `PlaylistDetail` currently invalidates shared generation and marks the entire result stale on every page fetch; distinguish append request lifetime from source/action authority narrowly, not by weakening security checks. Preserve exact selection tokens/manual IDs/context/current highlight, unselected-High origin, and separate list-versus-mini transport keys. Browsing/scroll/retry/preview never prepares music, claims a device or autoplays; complete-context Play remains separate from loaded browse extent and retains 1,000 limits.
6. **No mixed snapshots or false freshness.** Derived batches (including preview) must agree on revision where applicable, fence and consistent totals; cursor expired/409 or mismatch stops append, retains rows honestly stale/read-only and offers explicit refresh. Do not silently restart a cursor into the old prefix. Manual entry pages have **no revision field**: use existing summary revision/count validation around bounded append reads against the retained baseline before publishing; do not infer revision from offset or claim server snapshot support. Preserve reorder's stronger complete-snapshot contract. Catalog pages carry revision and holder already has known/pending revision logic: reconcile through it, never label mixed revision prefix current. Playlist index/chooser/likes envelopes lack a universal snapshot token; retain real available personal-change/generation/validation signals and fail truthfully on detected change, without inventing stronger backend guarantees. Explicit reset starts a fresh coherent prefix.
7. **Failure is latched, not an auto-retry loop.** A failed append retains rows, scroll, selections and its exact failed offset/cursor; explicit Retry tries **that same batch once**, not a whole-list reset, next skipped page, or repeated write. No automatic retry because the footer stays visible, a heartbeat/poll arrives, or Back/tab restoration re-enters the same failed state; fresh deliberate Retry or valid source reset is required. Errors/loading/end announcements are concise, transition-based and nonspamming. Preserve independent healthy sections, partial-error truth and existing stale recovery rather than claiming end/success after an invalid page.
8. **Keep selection and recovery safe.** Add-target append never resets an already chosen target or implicitly adds/creates. Append in verification remains read-only: duplicate names/rows cannot establish a lost create/add result or clear blocked write authority. Retain explicit verification, confirmations, retained drafts and uncertain-write no-replay safeguards. Preview edits invalidate the entire preview generation; only explicit Refresh preview can establish a new chain. Dedicated reorder still uses complete bounded order, not only scrolled rows. Preserve font scaling, 48dp Retry/More, native Back (IME/menu before route), tab/query/list state and last-row reachability above the dock.
