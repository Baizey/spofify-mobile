# Validation

Read [mobile-ux.md](mobile-ux.md) and [ui-validation.md](ui-validation.md) before changing a screen. Follow [worktree-review.md](worktree-review.md) for dedicated worktrees, exact-SHA review, separate guarded/advisory-locked shared-cache builds, standing conditional assigned-scope self-integration in **main**, and evidence-preserving cleanup after scoped/combined validation. Temporary integration branches are optional, not the final destination. **Automated checks and rendered native validation are separate gates.**

## Storage preflight and cleanup

[Storage hygiene](storage-hygiene.md) is part of every build/test/capture run, including delegated work. Before starting, check temporary/output capacity and visible quota, assign bounded owned scratch, and verify the forked test JVM temporary directory (`TMPDIR` alone is not enough). Preserve necessary reports/evidence, then clean verified disposable scratch after all owning processes stop; account for failure/cancellation/crashed descendants. Keep logs and tool output bounded. EDQUOT/ENOSPC stops artifact generation pending investigation and safe cleanup, not blind retries. The historical incident lesson and mandatory handoff checklist are in that document. These obligations do not relax the separate build lease or isolated-AVD safety checks.

## Automated gate

Use the provisioned API 37.0 compile platform via the worktree's local SDK configuration; minimum Android remains API 26 and target SDK remains 36. Assigned leads may acquire BUILD themselves: successfully atomic-`mkdir` the absolute common-directory `spofify-build.guard`, record their owner token, then acquire exclusive `spofify-gradle.lock` under the [guard/lease protocol](worktree-review.md#shared-resource-guards-and-advisory-leases). Flock alone does not coordinate across pi.lot Bash mounts. Verify no uncoordinated build is active, then run from their own worktree while continuously holding both:

```sh
GRADLE_USER_HOME=/var/home/lsm/repos/spofify-mobile/.tooling/gradle \
  ./gradlew :core:test :app:testDebugUnitTest :app:assembleDebug \
    :app:assembleDebugAndroidTest :app:lintDebug --offline --no-daemon --console=plain \
  -Pspofify.realBrokerIntegration=true
```

Ordinary unit runs omit `-Pspofify.realBrokerIntegration=true` and exclude only the `dev.spofify.mobile.testing.RealBrokerIntegration` JUnit category. They remain portable without a Go executable or sibling checkout; all ordinary synthetic/security/coordinator/adversarial tests still run. The **mandatory feature-delivery/CI integration gate above** sets the property to run **all ordinary plus real-broker integration tests**, with zero assumptions/skips/fake fallback. A malformed property value fails configuration; selecting integration with missing or mismatched prerequisites fails explicitly. Default fast-unit success alone is not full integration acceptance.

The integration tests require a **private, immutable pinned real Go executable**, not a live backend. Set `SPOFIFY_TEST_GO_BROKER_BINARY` to its explicit absolute path, anywhere in owned tooling; no repository-specific default, download or sibling-checkout dependency is embedded. Source pin: `b6eb54ffdc91e07e2ce7824b8be5f90afa8b05eb`; artifact SHA-256: `425e4bb46efcf1c25e195d92d4d1845ed2389cd35e6ebf9ad8981cd80c2c70f4`, verified before each launch. Provision that reviewed artifact through CI or copy a verified retained artifact read-only into private tooling. The pinned artifact and runtime currently require Linux; a different platform/artifact needs a separately verified pin, not checksum bypass. Never launch with cwd/data/cache in a Go checkout.

Optionally set common `SPOFIFY_TEST_GO_BROKER_RUNTIME_ROOT` to a supervisor-owned mmap-capable base. Every fixture allocates/removes only its own unique child, never the base or a peer's directory/database. If omitted, the lifecycle fixture preflights and records its own unique private `/dev/shm` child, monitors a 128MiB limit, awaits its child/helper shutdown and removes only that owned child. Quota headroom remains explicitly unknown. For delivery/CI use an outer supervisor-owned base so abnormal fork termination is also accounted and cleaned after descendant shutdown. Provision the common binary/runtime seams for every selected integration fixture, not only one feature's class.

The GitHub Android acceptance workflow also selects the integration category. Its explicit repository variable `SPOFIFY_TEST_GO_BROKER_ARTIFACT_URL` must identify the reviewed immutable HTTPS artifact (no URL credentials/query/fragment). CI bounds the download, verifies the same SHA-256 before use, preflights private storage and exports the common binary/runtime variables. Missing/unconfigured/mismatched provisioning fails the job instead of publishing a default-only green APK. This configuration does not invent or provision a remote artifact by itself; repository administrators must supply it. No artifact download or hosted CI execution is implied by local validation evidence. After tests, CI removes the shared runtime base only if empty; a leftover child/root fails cleanup rather than being swept while potentially live.

The runtime must support SQLite's required filesystem operations. A matched bootstrap probe found the repository FUSE path failing during `open_database`, while the same binary/environment with private `/dev/shm` runtime reached HTTP readiness. Use separately preflighted tmpfs only with explicit ownership and a monitored 128MiB broker-runtime budget; no native-AVD or general scratch relocation is implied. Each test starts an isolated loopback server with sanitized provider-free environment and synthetic credentials, and keeps it alive across the lifetimes under test. No catalog/media/admin import is needed. The supervising invocation must retain root/path/token evidence, account for all broker/test/Gradle descendants and remove only its runtime after actual shutdown/ECHILD. The Kotlin helper performs normal per-server termination/cleanup; it does not replace the outer crash/cancellation supervisor. Normal JVM scratch still needs separately verified `java.io.tmpdir` and its own budget.

The absolute cache above is shared and its use must be serialized; Git indexes and build outputs remain worktree-local. Release BUILD only after actual build/daemon writers stop and results are recorded, with owner-token-checked guard removal; preserve interrupted/uncertain ownership for explicit recovery. No overlapping builds. **All Gradle runs, including root/main postchecks, acquire BUILD only; there is no custom Git/MAIN guard or flock dependency.** Coordinate root builds with the parent/other leads to prevent source mutation, checking the intended SHA and clean source/index before and after. If source changes, report/revalidate rather than claim that SHA passed. Normal Git operations and integration follow [worktree-review.md](worktree-review.md#main-workflow-reviewed-squash-with-normal-git-locking). CI uses JDK 21; local validation uses JDK 25. APK paths can be under `outputs/` or `intermediates/`, depending on AGP; the native runner finds the actual artifacts.

Core tests use MockWebServer, never the live backend or real accounts. Synthetic in-process/loopback fixtures are allowed; they do not authorize external network diagnosis or live-backend access. They cover explicit HTTP/HTTPS origin admission (hostname/public/private/IPv6 HTTP, without DNS classification), invalid-origin rejection, exact scheme/host/effective-port isolation, opaque IDs, authentication/CSRF, cookies, redirect refusal, intact TLS defaults, one-shot writes, session-generation races, cancellation, transport bounds, catalog paging/revisions and personal/derived collections.

App JVM/Robolectric tests cover automatic encrypted latest-success login saving/autofill, legacy false-flag migration, failed/partial/cancelled/stale auth fences, identity-edit secret clearing, edits surviving error/retry, invalidated/corrupt storage and post-auth save failure preserving the session/prior record. Verify the successful triple wins over a later failed server preference, logout/expiry retains it, and autofill/offline retry never posts a password or autoplays. Preserve storage redaction/nonserialization, encryption namespace/random-IV/failed-commit and backup exclusions. They also cover stale-session fences, search/navigation/state, playlist builders, likes, queue/occurrence selection, playback coordination/progress, bundled typography and the full offline font-license asset/dialog through signed-in Profile → Credits. They are **not** native screenshot or physical-hardware tests.

Re-run the gate for each candidate and use its current XML reports, APKs and lint output. Historical test totals and ignored logs are not validation of the current SHA. Inspect packaged font faces and the complete OFL notice when changing typography/licensing assets; record remaining warnings rather than assuming an old count is current.

## Required native AVD gate

Normal isolated synthetic AVD validation is allowed. After the guarded automated build above and release of BUILD, acquire standalone NATIVE (`spofify-native.guard` plus `spofify-native.lock`) under the same owner/recovery protocol; never nest NATIVE inside BUILD. Reuse those exact APKs (verify their recorded hashes):

```sh
tools/ui/validate-native.sh --skip-build
```

The runner's default build does not supply `--offline`, so do not use it to bypass the exclusive build lease and offline gate. The runner uses a dedicated synthetic AVD, disabled ADB mDNS/wireless discovery and USB transports, an explicitly selected loopback emulator transport, and a fixture server inside the emulator. Its native test also rejects a non-emulator before Activity launch or test writes. Agents must not target real phones, personal AVDs or live accounts. Do not use an unqualified `adb install` or arbitrary-device `connectedAndroidTest`.

**Open and actually inspect screenshots**, exercise the changed flows, fix regressions, and recapture. Passing instrumentation without image review is not visual approval. Record the APK hash/revision, image/API/viewport, font scale, actions, image paths, findings and reviewer. Compare before/after when a baseline exists and answer the [mobile rendered-review checklist](mobile-ux.md#rendered-review-questions--answer-with-evidence-not-source-assertions). An independent reviewer inspects affected screenshots; fix non-nit findings and re-review until clean.

## Native acceptance checklist

Use synthetic fixture accounts/library data, not the live backend.

1. Sign-in: minimal labeled Server URL / Username / Password, named reveal/hide, Sign in, progress and concise invalid/auth/network error/recovery. No HTTP warning/consent, remember checkbox, saved-for/Use/Forget controls or font-license entry. Exercise explicit HTTP/HTTPS origins including hostname/public/private/IPv6 HTTP with synthetic fixtures; backend refusal remains a truthful error, not a client restriction or downgrade. Verify masking/re-concealment, IME Next/Done and duplicate-submit guards, preserved edits on error/retry, identity-change secret clearing, busy/retry reachability and Back at 320dp/font scale 2 with long values. Autofill the latest successful triple after logout/relaunch/expiry, never auto-submit or mix it with a failed later origin. Open the full JetBrains Mono notice offline via Profile → Credits and dismiss with Android Back; subsequent Back returns Credits to Profile, while Profile root allows normal Android root Back.
2. Home/Search: bounded personal shelves, real Liked Songs counts, no fabricated recommendations or empty-query catalog fetch; bottom query reachable with IME; hide bottom navigation and unnecessary/blank toolbar during active editing and restore on edit end. Keep grouped ordering without visible result-type title/count rows, retaining non-verbal/accessibility type cues. Automatic bounded append near each visible group frontier, stable rows/scroll, true-end stop and explicit latched-batch Retry; no offscreen drain, fetch-more buttons, persistent filters, tiny paging controls or empty-group message walls.
3. Navigation: native Back dismisses IME, then menu/sheet, then nested route without double-pop. Tabs and detail returns preserve query/scroll/playback. No duplicate in-app Back arrows.
4. Details/playlists: meaningful entity names, credits, long/Unicode names, missing art/audio, duplicate/unavailable entries, manual editing and derived recipe labels/evaluation/error recovery. Keep useful content during refresh and stale-revision revalidation.
5. Playback: full/capped contexts and late selections; seek, previous/restart, next, shuffle, repeat and occurrence-aware queue operations/Undo. Collapse Now Playing with Back or downward dismissal without changing audio, position or queue. Browsing/enqueue/reconnection never starts audio.
6. Lifecycle/auth: rotation/recreation, leaving/backgrounding the Activity, notification/system media controls, no autoplay after restart; logout/expiry stops buffered output and stale work cannot affect another account/server. History requires actual progress, not preparation/seeking.
7. Device sheet: truthful view-only state without registration, and correctly gated selected-output controls when registered. Exercise exact authority-fenced handoff with synthetic endpoints where applicable; a picker or enabled source is not proof of successful transfer. See [device-playback.md](device-playback.md).
8. Accessibility/layout: narrow viewport, increased font scale, JetBrains Mono wrapping and Android Unicode/emoji fallback, contrast, 48dp targets, TalkBack labels, bottom/gesture/IME insets, last-row reachability and accessible alternatives to music gestures. Check complete visible-row counts, aligned compact art/title plus one inline credit/metadata line, modest artist type and uniform row/action geometry across artist counts, availability and refresh. No stacked artist buttons; preserve rich artist/album actions through details/More. Mini-player is full-width and flat, not a rounded floating card.
9. Storage/privacy: origin-bound encrypted sessions and a separate automatically remembered latest-success login; failed/partial/cancelled/stale attempts cannot overwrite it. Verify legacy false flags do not suppress saves, corrupt/invalidated storage fails closed to manual login, and post-auth save failure retains the valid session/prior durable record with a truthful notice. No secrets in saved UI state, StateFlow, parcels, URLs or plaintext logs/preferences; no backup/device transfer, audio cache or authenticated image disk cache. Every API/art/audio/range request remains on the exact scheme/host/effective-port authenticated client; redirects fail safely and TLS verification stays intact.

## Hardware-specific limits

Emulators cannot establish every Bluetooth/vendor/codec/power-management behavior. Describe the precise unverified behavior and coordinate an exceptional check **through the user**, if needed; agents do not directly connect to or install on physical phones. Hardware access is not a routine prerequisite for ordinary emulator-validated work. No universal codec support or native runtime handoff approval is claimed.
