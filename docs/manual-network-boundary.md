# Manual network policy

The normal app injects `PreferenceManualOfflineStore`; with no store a repository remains online-only. Call `start()` before offering mode changes. Policy and the encrypted session are separate: a preference alone cannot supply an identity. Unknown/unreadable policy denies bootstrap as well as feature traffic. Retry can reread it. No remembered-login lookup, transport creation, or server validation is needed to restore a structurally valid encrypted `StoredSession` in manual mode. Local availability means previously verified here, not currently authorized by the server.

Use **local** `AuthState.Authenticated.identity` for navigation, local data and account scoping. Do not key navigation by the network generation. Use `onlineGrant` for online worker lifetimes and source selection: a verified local account with no grant has no network data source, including during return validation. In-place HTTP `renew()` leaves an existing grant/socket alone. Explicit logout and current-credential 401 remove local access and order the durable clear as before. Logout never calls the server in manual mode. As with online sign-out, a failed encrypted clear cannot guarantee restart-safe sign-out.

* `setManualOffline(true, beforeDisconnect)` is a serialized, durable **manual** command. Call it from the mode controller, not from a network-owned job. A failed preference write throws before changing mode. After the write, the app cancels pending playback admission and closes the existing socket without sending a playback command or waiting for the server. Starting in manual Offline skips server validation and does not open a playback socket. Entering Offline keeps the current queue in memory: the local owner can continue independently, and a follower keeps the last confirmed shared queue paused.
* Mode entry fences the grant, cancels the existing auth/feature jobs and transport, closes transferred streams, and joins retired repository-owned work. `withOnlineGrant(grant) { ... }` extends this ownership to structured worker children: wrap the **whole** load (including parsing, delayed retries or event collection), not just its HTTP call. Use `publishIfCurrent(grant) { ... }` for a short synchronous state write if a result has crossed another queue. Gate retirement is cancellation, not an endpoint error. Do not launch unrelated detached jobs from the owned scope.
* An already authenticated account remains authenticated throughout manual entry and return validation. `setManualOffline(false)` starts ordinary session validation without password replay. Only success grants a fresh generation. An unavailable server keeps the local identity with no grant; retry/refresh may validate again. Invalid/mismatched responses grant no access. A current 401 revokes. Compose fresh server state from the new grant, never from queued local commands or offline play receipts.

## Android transport and worker scope

`OkHttpAuthApi` owns auth/ordinary feature calls. Remote logout is tracked separately from durable session clears. `OriginMediaTransport` owns WS upgrade, audio range and versioned fill calls; socket send/receive and buffered audio reads also check captured authority. The library, search, personal/history, track content and offline API clients use repository exchanges. Coil's `Cover` fetcher calls `LibraryApi.artwork`; Media3's `ProgressiveMediaSource` uses `SessionAudioDataSource`, not a general HTTP URL data source. Android appearance is local and makes no network requests.

The Android connectivity callback, playback reconnect and maintenance timers, cache/prefetch workers, Coil consumers and feature viewmodels have app-owned lifetimes. A transport gate denies their requests but does not unschedule a detached timer or retract an event already in its consumer. Scope online workers and publications to the grant, and compose local sources separately.

Network loss alone does not persist Offline. With a validated grant, playback gets one batch of four serial connection attempts at startup or after losing an established socket. There is no delay between attempts; each has one 10-second deadline for admission and the first valid snapshot. If all four attempts fail while the grant is still current, the app writes the Offline preference. Once persisted, no further playback connections are attempted until the user goes online again.
